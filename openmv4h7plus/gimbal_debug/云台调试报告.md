# OpenMV 双轴云台调试报告

最近核对日期为 2026-11-20。对应程序为 [gimbal_debug.py](./gimbal_debug.py)。后续调试沿用本文件：程序改动同步更新当前配置，实机反馈按日期追加，角度记录注明测量起点。

## 当前接线与配置

OpenMV H7 Plus 控制两路信号，舵机使用独立电源。接线方案中 OpenMV GND 与舵机电源负极共地。

| 轴 | 舵机 | 信号线 | 程序通道 |
|---|---|---|---|
| 水平，底部转盘 | 型号待确认 | 白线接 P8 | Servo(2) |
| 俯仰，上方支架 | WHEELTEC S20F，标签勾选 180° | 黄／橙线接 P7 | Servo(1) |

俯仰正位已由用户在实机上确认：`TILT_CENTER_DEG = -5`。后续以此位置作为俯仰相对 0°。据用户现场反馈，俯仰舵机被撞歪，向后（靠线方向）实际只能到约 80°，无法达到 90°。

当前脚本使用 `TEST_MODE = "both"`、`TEST_ANGLE = 90`。启动时创建两个通道，俯仰给 −5°、水平给 0°，等待一秒。随后先测俯仰、再测水平，两个通道持续输出，另一轴保持正位。单轴测试仍将未参与的信号脚拉低。

水平测试按目标实际角度输入。程序依据实测点，取目标角度乘以 60/90 后四舍五入至整数度，作为水平舵机指令。`pan` 和 `both` 共用此换算。反向和其他幅度采用同一比例估算，实际精度待复测。

## 调试程序怎样运行

脚本从上往下执行，先检查 `TEST_MODE`。模式名拼写错误会在创建舵机通道前报错。有效模式决定启用哪些引脚，以及测试何时结束。

| 模式 | 启动与动作 | 结束条件 |
|---|---|---|
| `tilt_center` | P8 拉低，只创建俯仰通道，发送 −5° 正位指令 | 持续保持，直到在 IDE 中停止 |
| `tilt` | P8 拉低，只创建俯仰通道，以 −5° 为基准测两侧 | 一轮后回正，脚本结束 |
| `pan` | P7 拉低，只创建水平通道，以 0° 为基准，按水平比例测两侧 | 一轮后回中，脚本结束 |
| `both` | 两通道各创建一次，同时期保持输出；两轴归位后等待 1 秒，先测俯仰，再测水平 | 两轴各完成一轮后结束 |

表中的单轴引脚处理对应当前设置 `ISOLATE_IDLE_SIGNAL = True`。在 `both` 下，切轴只是把下一个目标发给另一个已有通道；此前的轴继续收到正位脉冲。此顺序已通过切轴无额外摆动的实机复测。

### 从目标角度到舵机指令

`test_axis()` 依次取相对目标 `0 → +TEST_ANGLE → 0 → −TEST_ANGLE → 0`。正位模式只取第一个 0。每一步使用同一公式 `command_deg = center_deg + round(relative_deg × ratio)`。

| 当前幅度 90° | 正位指令 | 比例 | 一轮实际发送的指令 |
|---|---:|---:|---|
| 俯仰 | −5° | 1 | −5° → +85° → −5° → −95° → −5° |
| 水平 | 0° | 60/90 | 0° → +60° → 0° → −60° → 0° |

每个测试点调用 `servo.angle(command_deg, 500)`，给驱动 500 ms 过渡时间。发出指令后等待 1.2 秒，读取驱动报告的脉宽，再留 1.8 秒观察，因此相邻指令间隔约 3 秒。串口中的 `relative_deg` 是相对目标，`command_deg` 和 `target_deg` 都是换算后的指令，`driver_pulse_us` 是驱动侧脉宽。实际机械角度仍由实物测量。当前调试脚本会发出完整测试序列，尚未按后倾约 80° 的实测行程限制指令。

## 角度实测 · 2026-11-20

已恢复逐点测角流程，移除 A/B/C 排查阶段及其两次启动等待。单轴模式先拉低闲置轴的信号脚，随后直接开始测角。每个目标位置留出 3 秒用于动作和读数。

| 轴 | 程序指令 | 实物观察（用户反馈） |
|---|---|---|
| 水平 | 从中位发 60° | 从中位到该侧约 90°。此项作为当前水平轴的参考点。 |
| 水平 | 两端分别设为 −90° 和 +90° | 左端经中位到右端总共约 240°，左右单侧角度未分别测量。 |
| 俯仰 | 从中位分别向两侧发 90° 幅度的指令 | 向前约 90°，向后（靠线方向）约 80°。后续现场反馈确认为舵机被撞歪。 |
| 俯仰 | 初始姿态及 ±45° 测试 | 用户目测初始姿态相对竖直向前偏约 3～6°，45° 测试时前侧略多、后侧略少。初始姿态是否为通电执行 0° 后的位置，以及两侧相对该位置的转角，待测量。 |

上述读数用于手头这套机构。水平轴的单点读数和两端总行程采用不同的测量区间，目前尚未建立全行程换算关系。

## 切换调试轴时旧轴移动 · 2026-11-20

| 测试条件 | 实机结果 |
|---|---|
| 切换单轴模式，在 IDE 点启动。在创建舵机对象前打印 A，创建时打印 B，发送第一条角度指令前打印 C。 | 用户观察到旧轴在 B 之后、C 之前移动。此时程序已经进入新通道初始化阶段。 |
| 在创建新通道前，将闲置轴的信号脚配置为推挽输出并拉低，再按相同方式切换。 | 用户复测反馈“ 不再动了 ”。当前单轴调试保留此设置。 |

这次对照支持闲置轴信号状态与现象有关。旧轴引脚的实际波形尚未测量。拉低信号脚会停止向该轴发送位置脉冲，带载时能否保持姿态需另行测试。

### 双轴依次测试

用户在原版 `both` 模式观察到电机额外移动。第一轮排查曾在创建每个舵机通道前拉低另一轴的信号脚。

后续观察：用户反馈，轮到水平轴或俯仰轴时，新进入测试的轴均会小幅偏转并迅速回正。水平轴首条角度指令为 0°，俯仰轴为 −5°。程序已增加 `init_pulse_us`，记录创建通道后、发送首条角度指令前的驱动脉宽，可与首个正位的 `driver_pulse_us` 对照。尚无此次启动的实机脉宽读数。

2026-11-20 实机复测通过。当前双轴流程在启动时一次性建立两个通道，两轴持续接收位置脉冲，切换测试轴时直接复用已有通道。用户确认在 `both` 模式下切轴时已无额外摆动。
